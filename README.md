# AGENT HUB RADIO

**Claude · Codex · Cursor를 한 채널에서 함께 쓰는 로컬 에이전트 허브.**

여러 창에 같은 질문을 복사하는 대신, Coral로 연결한 에이전트에게 토론·독립 투표·역할 분담 작업을 맡기고 과정을 한 화면에서 확인합니다.

[빠른 시작](#빠른-시작) · [Coral 연결](docs/coral-setup.md) · [사용 가이드](docs/user-guide.md)

![에이전트별 색상과 말풍선으로 보는 대화](docs/screenshots/chat.png)

> **0.1.0 Alpha** · Windows 중심으로 검증했습니다. 화면은 공개용 예시 데이터를 넣어 실제 GUI에서 캡처했습니다. 실제 모델 실행 결과나 성능 측정 화면은 아닙니다.

## 세 가지 사용 방식

| 하고 싶은 일 | 사용 방식 | 결과 |
| --- | --- | --- |
| 함께 검토해 결론 내기 | **합의 토론** — 멘션한 에이전트들이 제안·질문·교차 검토 | 작성자를 제외한 검토자 모두가 같은 안을 승인한 결과 |
| 서로 영향 없이 의견 비교 | **독립 비밀 투표** — 같은 지문에 개별 판단 | 마감 후 선택과 근거 공개 |
| 코드·문서 등 결과물 만들기 | **역할 분담 작업** — 계획 → 구현 → 검토 담당자 지정 | 작업 사본, 변경 패치·ZIP·보고서 |

역할은 고정되지 않습니다. 사용자가 담당자와 순서를 정하며 같은 역할에 여러 명을 배정하면 순차 실행합니다. 검증 명령은 선택 사항이고, 생략하면 **테스트 미실행**으로 표시합니다.

같은 채널의 후속 대화에는 최근 작업 결과와 보류 이유를 전달합니다. 반대 방향은 토론의 **‘이 합의안으로 작업 준비’** 버튼으로 연결합니다.

## 토론은 짧게, 검토는 독립적으로

1. **독립 의견 준비:** 각자 주장 1개, 핵심 근거 최대 2개, 우려 1개를 준비합니다. 모두 제출할 때까지 서로의 의견은 비공개입니다.
2. **쟁점 확인:** 의견을 함께 공개한 뒤 대표가 차이점을 확인합니다. 필요한 상대에게만 질문하며, 의무적인 전원 재발언은 없습니다.
3. **최종안 작성:** 확인된 내용과 남은 쟁점을 한 번만 정리합니다.
4. **동료 검토:** 해당 버전의 실제 작성자는 자기 안에 투표하지 않습니다. 다른 참여자 모두가 같은 최종안을 승인해야 완료하며, 반대하면 수정 후 다시 검토합니다.

찬성은 짧게 표시하고 반대는 이유와 필요한 수정에 집중합니다. 조건별 검증 근거는 별도로 유지합니다. 작성자와 실제 승인자는 허브가 결과에 붙이며, **1인 참여는 ‘상호 검증 없음’**으로 표시합니다. 기존 토론 기록은 이전 검토 정책을 유지합니다.

3인 토론의 기본 경로는 **독립 의견 3 + 쟁점 확인 1 + 통합 1 + 동료 검토 2 = 7회 호출**입니다. 질문·수정·형식 복구에는 추가 호출이 필요합니다. 답변 길이는 지침으로 줄이며, 사용자가 요청한 코드나 중요한 근거를 잘라내지 않습니다. 실제 토큰 절감률은 별도로 측정하지 않았습니다.

채널의 **‘토론 MD 저장’**으로 대화와 토론 기록을 Markdown 파일로 내보낼 수 있습니다. 진행 중인 토론은 저장된 내용까지만 포함하고, 아직 공개되지 않은 독립 의견은 제외합니다.

## 빠른 시작

**Python 3.11+**가 필요합니다. Python 런타임 외부 패키지 의존성은 없습니다.

```sh
git clone https://github.com/kdkrkwhr/agent-hub.git
cd agent-hub
```

Windows:

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -e .
.venv\Scripts\agent-hub --desktop
```

macOS / Linux:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -e .
.venv/bin/agent-hub
```

첫 화면에서 **데모로 둘러보기**를 선택하면 계정·Coral 서버·모델 호출 없이 UI를 체험할 수 있습니다. 기본 주소는 `http://127.0.0.1:8768`입니다. Windows의 `--desktop`은 Edge 앱 창을 사용합니다.

### 실제 에이전트와 연결하려면

1. 사용할 **Claude Code / Codex CLI / Cursor Agent**를 설치하고 각 CLI에서 로그인합니다.
2. [Coral 설치 가이드](docs/coral-setup.md)에 따라 **공식 coral-server v1.4.0 JAR**과 Java를 준비하고 관리형 구성을 설정합니다. **AgentRadio 설치는 필요하지 않습니다.**
3. Hub를 실행해 연결을 확인합니다. 관리형 구성에서는 서버 시작과 세션 준비를 처리하며, 기존 서버의 MCP 연결 정보를 직접 입력할 수도 있습니다.
4. **허브 자동 응답**을 켜고 채널에서 참여할 에이전트를 멘션합니다.

서버·CLI·계정은 이 저장소에 포함되지 않습니다. 서버 호환 범위와 설치 절차는 **[Coral 설치 가이드](docs/coral-setup.md)**에 정리했습니다.

## 데이터 보관

첫 데스크톱 실행에서 저장 폴더를 선택하면 다음 실행에도 같은 위치를 사용합니다. `--data-dir`로 직접 지정하거나 `--choose-data-dir`로 다시 선택할 수 있습니다. 폴더 재선택은 기존 데이터의 자동 이동을 뜻하지 않습니다.

```text
선택한 저장 폴더/
  storage.json   데이터 구조 버전
  config/        연결·모델·실행 설정
  database/      대화·토론·작업·알림 DB
  logs/runs/     에이전트 실행 기록
  logs/server/   허브 서버 로그
  workspaces/    프로젝트 작업 사본
  artifacts/     결과물
  backups/       이전 전 백업
  cache/         모델 목록·데스크톱 브라우저 프로필
  coral/         서버 설정·JAR·세션 정보·로그
```

선택 위치를 기억하는 런처 파일, 일반 브라우저의 화면 설정, 외부 CLI의 로그인·자체 기록은 별도로 관리됩니다. 기존 데이터 이전 절차와 보관 범위는 [Coral 구성 및 데이터 이전 가이드](docs/coral-setup.md)를 참고하세요. Coral 서버 재시작으로 사라진 스레드는 허브의 보관 기록에서 새 채널로 이어갈 수 있습니다.

## 알아둘 점

- **인증:** 모델 응답은 설치된 CLI를 통해 실행합니다. 구독 로그인과 API 인증의 지원 범위·한도·과금은 각 CLI 및 제공사 정책을 따릅니다.
- **속도와 비용:** 여러 에이전트의 호출·검토로 단독 실행보다 느리거나 사용량이 늘 수 있습니다. 합의가 정답을 보장하지는 않습니다.
- **파일 변경:** 토론·투표는 읽기 전용입니다. 역할 작업은 커밋된 Git 저장소의 별도 사본을 수정하며 원본 반영·커밋·push는 완료 후 미리보기에서 사용자가 실행 범위를 선택합니다.
- **보관:** 작업 사본·로그·결과물은 자동 삭제되지 않습니다. 접속 설정과 로그는 비공개 데이터로 관리하세요.
- **실험 기능:** Claude·Codex의 0-turn 수신은 별도 수신 호출을 줄이기 위한 선택 기능입니다. 메시지 토큰은 사용하며 전체 비용 절감을 보장하지 않습니다. Cursor는 다음 호출에서 묶어 전달합니다.
