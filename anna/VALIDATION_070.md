# 0.7.0 기능 우선순위 검증

검증일: 2026-10-22. 이 문서는 개발자 검증이며 실제 고객 인터뷰나 반복 사용을 검증한 결과가 아니다.

## 자동 검증

- 단위 테스트 86개 통과.
- 브라우저 테스트 47개 시나리오 통과. 전체 실행에서 기존 영문 안내 문구를 기대하던 설정 테스트 1개가 실패하여 새 문구로 고쳤으며 해당 설정 테스트를 재실행했다.
- strict manifest validation 통과.
- 브라우저 검증은 모의 SDK/AI를 사용한다. 빠른 검토 4회, 기존 심층 토론, 투표 비공개, 저장 장애 시 중단·AI 없는 저장 재시도·채널 전환 후 복구, 빈 응답, 형식이 다른 최종안, 360px 화면과 한국어·영어를 포함한다.

## 실제 Anna API 비교

설치 UI와 별도로 Anna 개발 세션에서 실제 `llm.complete` 요청을 수행했다. Host API와 동일한 MCP 인자를 전달했고 테스트 기록은 메모리에만 저장했다.

입력: 개인 개발자를 위한 작업 기록 앱. 혼자 2주간 하루 2시간을 쓸 수 있고, 기존 기록 보존과 추가 서버 비용 억제가 필요하다. 후보는 빠른 메모, 프로젝트 필터, AI 주간 요약, 실시간 공동 편집, 테마 10종이다.

단일 응답 비교도 동일한 입력과 5개 결과 항목을 요구했다. 호출마다 실제 모델은 `google/gemini-3-flash-preview`였으며, 기본 모델 선호를 그대로 사용했다.

| 방식 | 호출 | API 호출 시간 합계 | 입력+출력 토큰 | 결과 |
|---|---:|---:|---:|---|
| 빠른 검토 | 4 | 약 10.7초 | 2,914 | 3개 의견 후 5개 항목의 최종안 생성 |
| 단일 응답 | 1 | 약 3.3초 | 812 | 같은 5개 항목으로 최종안 생성 |
| 독립 투표 | 3 | 약 4.6초 | 1,199 | 3개 유효 표, 모두 메모+필터 선택 |

시간은 이 한 번의 API 실행 측정이며 서비스 속도를 보장하지 않는다. 토큰은 API 응답의 usage 합계이고 청구액이 아니다.

### 무엇을 배웠나

두 방식 모두 메모 입력과 프로젝트 필터를 먼저 추천했다. 따라서 **여러 역할이 단일 응답보다 더 나은 결정을 내렸다고 볼 근거는 없다.** 빠른 검토의 토큰 사용은 이번 사례에서 약 3.6배였다.

빠른 검토에는 기존 데이터의 저장 형식·마이그레이션을 확인하고 샘플 10건으로 필터를 점검하라는 제안이 포함됐다. 단일 응답에는 사용자가 태그를 직접 입력할 의향이 있는지 검증하라는 제안이 있었다. 서로 다른 확인 항목을 제시했지만 어느 쪽이 실제 사용자에게 더 유용한지는 아직 확인하지 않았다.

두 응답 모두 근거가 부족한 단정이 남았다. 예를 들어 협업의 구현 가능 시간이나 비용을 확정적으로 표현했고, 빠른 검토에서는 입력의 ‘추가 비용 억제’를 ‘서버 비용 0원 유지’로 확대했다. 화면에 사실 확인과 사용자 판단이 필요함을 안내하며, 합의를 검증된 사실처럼 홍보하지 않는다.

초기 검증 도구의 CLI SamplingBridge 변환 경로는 Host API의 `systemPrompt` 등을 그대로 보존하지 않았다. 해당 실행은 비교 결과에서 제외했고, UI와 동일한 요청 인자를 전달하도록 검증 어댑터를 수정한 뒤 위 수치를 얻었다. 앱의 실제 요청 형식은 변경하지 않았다.

## 설치된 Anna UI 확인

working revision 5를 소유자 draft에 설치한 뒤 Orca로 실제 UI를 조작했다. 빠른 검토 4개 응답과 투표 3개 응답이 정상 완료됐고, 모두 실제 모델 `google/gemini-3-flash-preview`가 표시됐다. 투표 진행 중에는 선택이 가려졌고 완료 후 A 3표가 공개됐다.

결정 요약을 클립보드에 복사하고 채널 Markdown을 다운로드했다. 창을 닫고 다시 연 뒤에도 완료 기록 2건과 기존 채널이 유지됐다. 테스트 중 바꾼 정리자의 모델 계열은 원래 값으로 복구했다. 기존 기록의 모델 오류는 임의로 재시도하지 않았다.

실제 창과 사무실 화면을 캡처해 확인했다. 360px 레이아웃은 모의 브라우저에서 확인한 결과이며, Anna 호스트의 좁은 창 최종 검증이나 모바일 플랫폼 지원 확인과 같지 않다. 실제 설치 환경에서 심층 토론과 별도 계정 격리까지 검증한 것은 아니다.

## 1.0 전 필요한 추가 확인

- 후보들이 비슷하게 매력적인 실제 출시 고민에서 역할별 의견이 단일 응답보다 읽을 가치가 있는지 비교한다.
- 3~5명의 개인 개발자가 설명 없이 첫 요청을 완료하고, 결과를 보고 실제로 결정하거나 다시 사용하는지 확인한다.
- 역할 구분, 남은 반론, 가정과 사실의 구분을 평가한다. 좋은 결과 한 건만 골라 정확성 향상으로 표현하지 않는다.
- 설치 앱의 심층 토론, 모델 선호 불일치, 별도 계정 격리, 여러 기기 충돌, 대량 기록 저장 한도 등을 추가 검증한다.
