# Agent Hub Radio · Anna 앱

**다음 출시에서 무엇부터 만들지, 분석가·비판자·정리자의 의견을 나란히 살펴보는 AI 회의실입니다.**

혼자 기능 목록을 정리하다 보면 하고 싶은 일이 계속 늘어나죠. 대상 사용자, 이번 목표, 개발 여력과 후보 기능을 적으면 먼저 만들 것과 미룰 것, 확인할 가정까지 정리합니다.

현재 **0.7.1 소유자 테스트 draft**를 개발 중입니다. 공개 출시 전이며, 첫 심사 목표 버전은 **1.0.0**입니다. 이 저장소의 [로컬 CLI 제품](../README.md)과 실행 방식이 다릅니다. Anna 앱에서는 별도 서버나 Claude Code·Codex CLI 설치 없이 Anna AI를 사용합니다.

## 처음 사용하기

1. Anna에 설치된 Agent Hub Radio를 열고 **새 채널**을 만듭니다.
2. **기능 우선순위 예시**를 누릅니다. 예시는 입력창만 채우며 AI를 호출하지 않습니다.
3. 제품, 사용자, 목표, 개발 여력, 후보 기능을 자신의 상황에 맞게 고칩니다.
4. **빠른 검토**와 참여 역할을 확인한 뒤 **보내기**를 누릅니다.
5. 결과의 **먼저 만들기 / 미루기 / 판단 근거 / 확인할 가정 / 다음 행동**을 읽습니다. 전체 의견을 펼치거나 결정 요약만 복사할 수도 있습니다.

이미 입력한 글은 예시 버튼으로 덮어쓰지 않습니다. 모델이 지정한 형식을 따르지 않아도 답변 전체를 그대로 보여줍니다.

## 할 수 있는 일

| 기능 | 사용 방법 |
|---|---|
| 기능 우선순위 검토 | 먼저 만들 기능을 최대 2개로 좁히고 최소 구현 범위와 확인할 가정을 검토합니다. |
| 일반 주제 검토 | 입력창의 목적을 바꾸어 제품 아이디어나 문구 등 다른 고민을 검토합니다. |
| 빠른 검토 | 역할별 독립 의견을 받은 뒤 정리합니다. 별도 반박·동료 검토 단계는 없습니다. |
| 심층 토론 | 의견 → 반박 → 최종안 → 동료 검토를 진행합니다. 최종안 뒤의 검토 의견도 결과 영역에 표시합니다. |
| 독립 투표 | 지문과 선택지 2~6개를 입력합니다. 모든 역할의 처리가 끝나면 선택·기권·근거·우려를 확인합니다. |
| 채널과 기록 | 주제별 채널을 만들고 이름을 바꾸거나 닫을 수 있습니다. 기록을 다시 열고 Markdown으로 복사·내보내기하거나 삭제할 수 있습니다. |
| 사무실 | 역할이 어떤 단계에서 작업 중인지 지도에서 확인합니다. 지도 이동·열람에는 AI 호출이 없습니다. |
| 역할과 모델 | 성향과 모델 선호를 설정하고, 각 응답에 표시된 실제 모델을 확인합니다. 한국어·영어를 지원합니다. |

**각 요청은 독립적입니다.** 이전 채널 대화가 다음 요청의 배경으로 자동 전달되지 않습니다. 필요한 조건과 앞서 결정한 내용을 새 요청에 적어 주세요.

## AI 사용량과 판단의 한계

| 방식 | 참여 역할 N명 | 3역할 기준 |
|---|---:|---:|
| 빠른 검토 | N + 1회 | 4회 |
| 심층 토론 | 3N회 | 9회 |
| 투표 | N회 | 3회 |

AI 생성은 **사용자 Anna 계정의 AI 사용량**을 사용합니다. 호출 횟수는 토큰 수나 청구액과 같지 않습니다. 사용자가 선택한 재시도에는 추가 사용량이 발생할 수 있습니다. 설정 변경, 예시 채우기, 기록 열람, 복사와 저장만 재시도하기에는 AI를 호출하지 않습니다.

세 역할이 같은 모델을 사용할 수 있습니다. 역할 이름은 프롬프트의 관점이며 서로 다른 인간 전문가나 독립된 모델을 보장하지 않습니다. 모델 설정은 선호 조건으로 전달하며 실제 배정은 응답의 모델 이름으로 확인합니다. 투표에서는 다른 역할의 표를 입력으로 전달하지 않습니다.

AI의 합의나 다수결은 사실 확인이 아닙니다. 구현 공수, 비용, 사용자 수요 등은 직접 확인해야 합니다. 코드를 실행하거나 사용자 파일을 수정하는 앱도 아닙니다. [실제 API 비교 검증과 남은 한계](VALIDATION_070.md)를 함께 기록했습니다.

## 저장이나 응답이 실패했을 때

- **저장 안 됨:** 후속 AI 요청을 멈추고 받은 답변을 현재 화면에 유지합니다. **저장만 다시 시도**는 AI를 다시 부르지 않습니다. 저장 후 남은 단계는 사용자가 이어갑니다.
- **빈 응답·잘린 응답:** 완료로 표시하지 않습니다. 부분 결과를 확인하고 재시도 여부를 선택합니다.
- **중단·시간 초과:** 후속 요청을 멈춥니다. 이미 시작된 서버 생성까지 취소됐다고 보장할 수는 없으며, 재개 시 해당 미완료 단계의 AI 사용량이 다시 발생할 수 있습니다.
- **할당량·연결 문제:** 화면의 오류 안내를 확인합니다. 자동으로 유료 재시도를 반복하지 않습니다.
- **다른 창과 충돌:** 현재 답변을 먼저 복사한 뒤 **최신 저장 기록 불러오기**를 누릅니다. 다른 기기의 변경을 강제로 덮어쓰지 않습니다.
- **다른 창에서 진행 중:** 해당 창에서 중단하거나, 연결이 끊겼다면 최대 2분 30초 후 **기록 새로고침**을 누릅니다. 완료한 단계는 재실행하지 않습니다.
- **저장 한도:** 개별 기록 크기와 계정의 저장 공간 한도를 구분해 확인합니다. 큰 요청은 나눠 진행하세요. 이전 기록은 필요한 내용을 내보낸 후 정리할 수 있습니다.

미저장 답변은 현재 창의 메모리에만 남을 수 있으니 창을 닫기 전에 복사하거나 저장을 복구하세요. 기록은 개별 항목으로 저장하고 목록은 페이지 단위로 불러옵니다. 채널에는 최근 30개 기록을 표시하며 **MD 저장**은 해당 채널의 전체 기록을 내보냅니다. 일부 기록을 읽지 못하면 불완전한 파일을 다운로드하지 않습니다.

진행 잠금은 동시 실행을 줄이지만, 연결이 끊긴 요청의 서버 처리·과금 여부까지 보장하지는 않습니다. 0.7.1 이전 앱 창은 업데이트 후 다시 열어 주세요. 이전 앱의 무조건 저장까지 새 앱이 막을 수는 없습니다. [저장 검증 및 실제 설치 확인 범위](VALIDATION_071.md)를 참고하세요.

## 데이터는 어디로 가나요?

입력 내용과 역할별 생성 요청은 Anna Host API를 통해 Anna AI로 전달됩니다. 채널, 요청·응답, 진행 상태와 설정은 Anna의 해당 사용자 앱 저장소에 저장합니다. 개발자가 운영하는 별도 AI 프록시나 데이터 서버는 사용하지 않습니다.

화면에서 기록을 삭제하거나 Markdown으로 내보낼 수 있습니다. 앱의 삭제 기능이 플랫폼 백업·로그까지 즉시 삭제함을 보장하지는 않습니다. Anna 플랫폼의 보관 기간과 모델 제공자의 처리 정책은 Anna의 공식 정책을 확인해야 합니다. 비밀키나 불필요한 개인정보는 입력하지 마세요.

작은 창에 맞는 레이아웃을 제공하지만, 이것이 Anna의 Android/iOS 지원을 의미하지는 않습니다. 현재 manifest의 지원 환경은 데스크톱입니다.
