## 이번 측정의 결론

동일한 3개 과제의 2회 반복에서 ON이 전체 CLI 호출·경과 시간 중앙값·보고 토큰 합계를 줄였습니다. 모든 과제는 실행 중 수정 메시지와 도구 읽기를 포함한 제한된 조건입니다. 일반 업무 절감률 또는 정확도 향상의 증거로 확대 해석하지 않습니다.

- 요청 종료 시간 중앙값: OFF 171.1초 → ON 103.2초 (39.7% 감소). 보류 실행도 포함한 값.
- CLI 호출 합계: 59 → 42 (28.8% 감소).
- 보고 토큰 합계: 2,263,673 → 1,552,075 (31.4% 감소). 캐시 포함, 실제 비용·사용 한도 차감액 아님.
- 필수값+합의 성공: OFF 4/6, ON 6/6. 합의 자체는 OFF 5/6, ON 6/6. 표본이 작아 일반적인 정확도 향상을 입증하지 않음.
- ON 경계 수신 확인 12건, 일반 질문 호출 취소 12건. OFF의 기본 묶음 전달도 호출을 취소하므로 이 수치를 전체 호출 절감과 동일시하지 않음.

## 발견된 실패와 다음 개선점

`revision-r2-off`는 **잘못된 최종안에 전원 승인**했습니다. 늦은 질문에 명시된 revision 필수 조건을 원본 파일의 선택 옵션 설명보다 낮게 취급했고, 동료 질문·답변 과정에서 필수 조건을 철회했습니다. 최종 key_fields에서 revision을 누락해 같은 사용자에 대한 서로 다른 리비전이 캐시를 공유하게 됩니다. 메시지는 전달됐지만 조건 보존에 실패했습니다. 실행 중 수정 조건을 고정해 최종안과 대조하는 검증이 가장 중요한 후속 개선입니다. 합의 성공과 정답은 별개라는 실제 반례입니다.


`code-r2-off`는 JSON 필수값을 맞혔지만 전원 합의에 실패했습니다. Claude 후보에 `def total(n): if n<0: ...` 형태의 실행 불가능한 한 줄 Python 코드가 포함됐습니다. Codex가 이 문법 오류를 올바르게 반대했으나, 응답의 proposal_hash에서 한 글자를 누락해 HUB가 검토표를 거부하고 보류했습니다. 근거 없는 승인으로 통과시키지는 않았습니다.

- JSON 값 일치 검사는 코드 문법·실행 가능성 검증을 대체하지 못합니다. 제시 코드의 별도 검증이 필요합니다.
- 정확한 해시가 필요한 검토표의 단순 복사 오류에 대한 제한된 형식 복구가 다음 개선 후보입니다. 반대 의견을 보존해야 하며, 임의로 승인을 만들어서는 안 됩니다.
- ON도 이번 6회 모두 7번의 CLI 실행을 사용했습니다. 메시지 수신 때문에 새 호출을 만들지 않는다는 의미이며 전체 협업이 0회 호출이라는 뜻은 아닙니다.
- 비교 중 제품 코드·프롬프트 정책은 변경하지 않았습니다. 실패 실행을 재실행하여 대체하지 않았습니다.
