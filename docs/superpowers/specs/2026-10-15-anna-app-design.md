# Anna 앱 설계 · AGENT HUB RADIO 0.4.0

- 작성일: 2026-10-15
- 상태: 승인된 설계, 구현 전
- 대상: Anna 소유자 테스트 앱 `agent-hub-radio` **0.4.0**

## 목표

AGENT HUB RADIO의 토론·투표·사무실·역할 분담 작업을 Anna 웹 앱으로 제공한다. Anna 클라우드에는 사용자의 Claude Code·Codex·Cursor CLI와 로컬 작업 폴더가 없으므로, 에이전트는 **Anna AI가 연기하는 역할**로 바꾸고 역할마다 모델을 선택하게 한다.

## 범위

포함:

- 대화·토론, 독립 투표, 역할 분담 문서 작업, 사무실 화면, Markdown 내보내기
- 역할별 모델 성향·계열·실제 모델명 선택과 실제 사용 모델 표시
- 단계별 저장, 이어하기, 중단, 단계 재시도, 기록 보관·복구·삭제
- 한국어·영어 UI

제외:

- 터미널 CLI(`chat.cmd`) 기능, 코드 작업 사본·패치·검증 명령, 원본 반영
- Coral 연결, 로컬 Python 허브
- 역할 이름·성격 직접 편집
- 실제 Anna AI 호출 테스트(사용량 확보 후 별도 진행, 아래 "보류 검증" 참고)

기존 Python 허브, 터미널 CLI, `--desktop` 모드는 변경하지 않는다.

## 구조

방식은 **화면 주도(A안)**다. 실행 도구(Executa)를 두지 않고 앱 화면이 Anna Host API만 사용한다.

- `llm.stream`: 역할 발언(토큰 단위 표시). 구버전 호스트가 `-32601`을 반환하면 `llm.complete`로 대체한다.
- `storage.get/set/list/delete`: 사용자별 설정과 기록 저장
- `manifest.json`의 `ui.host_api`: `llm: ["complete","stream"]`, `storage: ["get","set","list","delete"]`

위치는 `agent-hub/anna/`이며 노트버디 저장소와 같은 구성을 쓴다.

| 파일 | 역할 |
| --- | --- |
| `anna/app.json`, `anna/manifest.json` | 스토어 정보, 권한 |
| `anna/bundle/index.html`, `app.js` | 진입점, 화면 전환 |
| `anna/bundle/ai.mjs` | Anna AI 호출 단일 창구, 모델 요청 조립, 실제 모델 기록. 테스트에서 가짜 구현으로 교체 |
| `anna/bundle/store.mjs` | 저장소 읽기·쓰기, 색인 복구, 큰 기록 분할 |
| `anna/bundle/roles.mjs` | 역할 정의, 지시문, 모델 설정 |
| `anna/bundle/discussion.mjs` | 토론 진행 |
| `anna/bundle/voting.mjs` | 투표 진행 |
| `anna/bundle/pipeline.mjs` | 문서 작업 진행 |
| `anna/bundle/office.mjs` | 사무실 SVG와 말풍선(기존 `office.js` 이식) |
| `anna/bundle/export.mjs` | Markdown 내보내기 |
| `anna/bundle/i18n.mjs` | 한국어·영어 문구 |
| `anna/tests/` | 단위·브라우저 테스트 |

진행 모듈(`discussion`·`voting`·`pipeline`)은 DOM을 모르며 `ai`와 `store` 인터페이스만 받는다. 그래서 가짜 AI로 단계와 호출 횟수를 단위 테스트할 수 있다.

Anna 번들 CSP는 인라인 스크립트를 막으므로 기존 화면의 인라인 이벤트 처리기는 외부 모듈로 옮긴다.

## 역할과 모델

기본 역할은 셋이며 모두 Anna AI 한 계정 사용량으로 동작한다.

| 역할 | 성격 |
| --- | --- |
| 분석가 | 근거와 구조를 짚는다 |
| 비판자 | 위험과 반례를 찾는다 |
| 정리자 | 합의안과 문서를 다듬는다 |

채널·작업마다 참여 역할을 고른다. 역할마다 다음을 설정한다.

- **성향**: 빠름(`speedPriority` 높음), 균형, 깊은 분석(`intelligencePriority` 높음)
- **계열**: 자동, Claude, GPT, Gemini → `modelPreferences.hints` (예: `{family: "claude"}`; 자동이면 생략)
- **사용해 본 모델**: 응답의 `model` 필드로 받은 실제 모델명(예: `google/gemini-3-flash-preview`)을 설정에 누적하고, 고르면 그 이름을 힌트로 우선 요청한다.

Anna 문서 기준으로 앱은 모델을 강제할 수 없고 모델 목록도 조회할 수 없다. 사용자가 Anna에서 켠 모델 안에서만 선택된다. 따라서:

- 모든 발언에 **실제 사용 모델명**을 표시한다.
- 요청한 모델과 실제 모델이 다르면 둘 다 표시한다.
- 설정 화면에 "Anna 설정에서 켠 모델만 사용됩니다"를 안내한다.

## 진행 흐름과 AI 호출 수

N은 참여 역할 수(기본 3)다.

**토론**: 1회차 독립 의견 N → 2회차 반박·보완 N → 정리자 최종안 1 → 작성자 제외 동료 검토 N−1. 3명이면 8회.

**투표**: 각 역할이 같은 지문과 선택지로 독립 판단 N. 모두 끝나기 전에는 선택을 숨기고, 끝나면 표수와 근거를 공개한다.

**문서 작업**: 계획 → 작성 → 검토 3회. 수정 요청 시 수정 1 + 재검토 1, 최대 5회. 유형은 자동, 조사·분석, 문서 정리, 기획·개선 네 가지. 결과는 Markdown.

공통 원칙:

- 실행 전 예상 호출 수를 보여 준다.
- 기존 답변 원칙(결론 먼저, 토론 발언 2~3문장, "자세히" 선택 시 길게)을 유지한다.
- 독립 의견과 투표 프롬프트에는 다른 역할의 발언·표를 넣지 않는다.

## 저장 구조

| 키 | 내용 |
| --- | --- |
| `settings` | 역할별 성향·계열·선택 모델, 사용해 본 모델 목록, 언어, 답변 길이 |
| `threads` | 목록 색인: id, 제목, 종류, 상태, 수정 시각, 보관 여부 |
| `thread/<id>` | 요청, 단계, 발언(역할·요청 모델·실제 모델·상태·본문), 결과 |
| `thread/<id>/<n>` | 기록이 커질 때 분할한 발언 묶음 |

- 단계가 끝날 때마다 `thread/<id>`를 먼저 저장하고 색인을 갱신한다.
- 앱 시작 시 `storage.list`로 색인과 실제 기록을 맞춘다.
- 키당 크기 한도는 문서에 없으므로 개발 하네스에서 확인해 분할 기준을 정하고 문서에 기록한다.
- 삭제는 재확인 후 실행한다.

## 오류 처리

| 상황 | 동작 |
| --- | --- |
| AI 실패 (`APP_QUOTA_EXCEEDED`, `APP_PROVIDER_ERROR`, 시간 초과) | 해당 발언을 실패로 표시하고 진행을 저장. "다시 시도"와 "이 역할 빼고 계속" 제공. 사용량 부족은 별도 안내 |
| 중단 | 스트림을 끊고 받은 부분을 "중단됨"으로 저장 |
| 창을 닫고 재진입 | 진행 중 기록에 "이어하기". 끝난 발언은 다시 호출하지 않음 |
| 저장 실패 | 화면 결과 유지, 실패 안내, 다음 단계 전에 재저장 |

## 테스트

모든 자동 테스트는 Anna AI 사용량을 쓰지 않는다.

- **단위(`node --test`)**: 단계 진행, 호출 횟수, 독립성 프롬프트 검사, 이어하기·중단·재시도, 모델 요청 조립과 실제 모델 기록, 내보내기, 색인 복구
- **브라우저**: Anna 개발 하네스에서 가짜 `ai.mjs`로 실제 화면 확인. 모델 선택 저장, 요청·실제 모델 불일치 표시, 사용량 부족·시간 초과 안내, 사무실 말풍선, 360px 모바일 폭
- **검증**: `anna-app validate`
- **CI**: GitHub Actions에 Anna 앱 작업 추가. 기존 Windows 도움말 인코딩 실패(`UnicodeEncodeError`)도 수정
