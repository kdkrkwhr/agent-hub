# 사용 가이드

[README로 돌아가기](../README.md)

## 실행과 종료

설치 방법은 [빠른 시작](../README.md#빠른-시작)을 참고하세요. 소스 상태에서는 Windows `start.cmd`, macOS/Linux `sh start.sh`로 실행할 수도 있습니다.

기본 주소는 `http://127.0.0.1:8768`입니다. Windows `--desktop`은 별도 Edge 앱 창을 사용하고, 다른 환경은 브라우저를 엽니다. 창을 닫아도 서버는 유지되므로 실행 터미널에서 Ctrl+C로 종료합니다. 네이티브 설치 프로그램과 백그라운드 서비스는 제공하지 않습니다.

## 첫 연결

데모는 계정이나 모델 호출 없이 UI를 체험하는 모드입니다. 실제 연결에는 별도 Coral 서버와 로그인한 CLI가 필요합니다. [Coral 설치 가이드](coral-setup.md)에 서버 배포물·호환 범위와 입력값이 있습니다.

1. 사용할 Claude / Codex / Cursor를 선택합니다.
2. Coral에 등록한 관찰자와 에이전트 MCP URL을 입력합니다. 기본 관찰자 `ops`는 실행 에이전트와 다른 신원이어야 합니다.
3. 필요한 프로젝트 경로와 CLI 실행 파일을 지정합니다.
4. 연결 테스트 후 저장하고 **허브 자동 응답**을 켭니다.

에이전트 선택은 기존 Coral 신원과 CLI를 연결하는 과정입니다. 서버 신원 발급·CLI 설치·서비스 로그인은 자동화하지 않습니다. Hermes/OPS는 외부 관찰자·대화 참여자로 사용할 수 있습니다.

자동 응답은 기본적으로 꺼져 있습니다. 켜면 새 멘션 요청이 로그인한 CLI를 호출하고 서비스 사용량이 발생합니다. 같은 Coral 신원에 다른 자동 응답기가 붙어 있다면 중지하세요.

## 연결 URL과 토큰 갱신

개별 URL 대신 저장소 밖 UTF-8 파일을 지정할 수 있습니다.

```text
ops|http://127.0.0.1:5555/<observer-mcp-endpoint>
claude|http://127.0.0.1:5555/<claude-mcp-endpoint>
codex|http://127.0.0.1:5555/<codex-mcp-endpoint>
cursor|http://127.0.0.1:5555/<cursor-mcp-endpoint>
```

형식 예시이므로 서버에서 발급한 실제 URL로 바꿔야 합니다. Hub는 연결할 때 파일을 다시 읽습니다. 서버 재시작 후 파일 갱신과 사라진 세션 재생성은 서버/설치 도구에서 담당하며 Hub가 토큰을 재발급하지는 않습니다.

현재 어댑터는 HTTP MCP initialize, `coral://state` 리소스와 Coral 스레드·메시지 도구를 사용합니다. 다른 서버 버전의 호환성을 보장하지 않습니다.

## 대화와 작업

- **대화:** 첫 요청에 멘션한 에이전트만 참여합니다. 진행 중 추가 메시지는 팀 변경이 아닌 추가 지침입니다. 다른 팀으로 새 요청을 하려면 다른 채널을 사용하세요.
- **독립 투표:** 지문과 선택지를 기준으로 개별 판단하고 마감 후 공개합니다. [투표 안내](voting.md).
- **작업:** 계획·구현·검토 담당자를 지정합니다. 원본과 분리된 사본에서 순차 실행합니다. [작업 안내](pipeline.md).
- **사무실:** 작업 상태를 공간으로 보여주며 추가 모델 호출은 발생하지 않습니다. 캐릭터를 눌러 내용을 확인하거나 대화로 이동합니다.

토론의 합의문은 **이 합의안으로 작업 준비**로 전달합니다. 작업 후 같은 채널의 새 토론에는 최근 종료된 작업 맥락을 고정해 제공합니다. 특정 과거 작업은 **이 작업에 대해 대화하기**를 사용하세요. 진행 중 역할 작업에 보낸 일반 메시지는 기록으로만 남으며 작업 조건을 바꾸지 않습니다.

첫 연결이나 자동 응답 재활성화 시 과거 멘션을 소급 실행하지 않습니다. 자동 응답을 끄면 관찰 모드가 되며 진행 중 협업은 취소됩니다. 실행 중 재시작된 작업은 보류하고 자동 재실행하지 않습니다. 중복을 줄이는 큐·전송 표식은 있지만 분산 환경에서 정확히 한 번 실행을 보장하지는 않습니다.

## 채널과 읽음 표시

채널은 상단 고정 후 최신 대화순으로 표시합니다. 이름 변경·고정·읽음 위치는 브라우저 프로필에 저장되며 다른 참여자에게 적용되지 않습니다. 브라우저 데이터 삭제 시 초기화됩니다.

읽지 않은 메시지에는 첫 방문 시 기존 기록도 포함됩니다. 대화 탭에서 필터 없이 맨 아래까지 읽으면 읽음 처리합니다. 다른 탭이나 숨겨진 창에서는 읽음 처리하지 않습니다.

**채널 닫기**는 영구 삭제가 아닙니다. 닫기 직전 기록을 로컬 DB에 보관하며 **닫힌 채널 표시**로 다시 읽을 수 있습니다. 다시 열기는 지원하지 않습니다. 실행 중 작업은 먼저 완료/취소해야 하고 대기 작업은 닫을 때 취소됩니다. 외부 에이전트는 Hub가 중지시킬 수 없습니다. 다른 클라이언트가 먼저 닫았거나 닫기 직전에 도착한 메시지까지 보관을 보장하지는 않습니다.

## 모델 설정

상단 **모델 설정**에서 에이전트별 다음 호출 모델을 선택하거나 ID를 입력합니다. 빈칸은 CLI 기본값입니다. 실행 중 호출은 유지하며 각 CLI의 전역 모델 설정을 수정하지 않습니다.

목록 새로고침은 설치된 CLI의 메타데이터를 조회합니다. 계정에서 사용할 수 없는 모델은 실제 실행 시 오류가 날 수 있습니다. CLI 출력에 실제 모델 정보가 없으면 추정하지 않고 미확인으로 표시합니다. Auto·별칭은 실제 실행 모델과 다를 수 있습니다.

## 데이터와 실행 범위

| OS | 기본 데이터 폴더 |
| --- | --- |
| Windows | `%LOCALAPPDATA%/AgentHub` |
| macOS | `~/Library/Application Support/AgentHub` |
| Linux | `$XDG_STATE_HOME/agent-hub` 또는 `~/.local/state/agent-hub` |

`AGENT_HUB_HOME` 또는 `--data-dir`로 변경합니다. `workspaces/`는 작업 사본, `runs/`는 실행 로그, `artifacts/`는 결과물입니다. 자동 정리하지 않으므로 용량이 늘어날 수 있습니다. 사본을 삭제하면 후속 대화에서 해당 파일을 직접 확인할 수 없습니다.

설정 파일은 접속 URL을 포함하며 암호화 저장소가 아닙니다. 개인 대화·인증 정보·실행 로그는 Git에 올리지 마세요. 서버는 루프백 전용이며 인터넷에 공개하는 원격 서비스가 아닙니다.

토론·투표는 읽기 전용이며 역할 작업의 구현 단계에서만 쓰기를 허용합니다. CLI 모드와 사본 분리가 모든 도구에 대한 OS 수준의 완전한 격리를 보장하지는 않습니다. 화면의 연결·작업 상태는 이 Hub 기준이며 외부 CLI의 로그인 상태나 외부 작업까지 추적하지 않습니다.


### 채널 보관과 삭제

열린 채널도 Coral 동기화 때 로컬에 저장합니다. 같은 연결 설정에서 세션이 종료되어 채널이 없어지면 `[보관]`으로 남고, 과거 멘션을 재실행하지 않습니다. `새 채널로 이어가기`는 새 Coral 채널을 만들고 최근 대화 10,000자를 참고 자료로 전달합니다. 전체 원본은 보관 채널에서 볼 수 있습니다. 이전 작업의 ID와 산출물은 원래 채널에 유지됩니다.

닫힌 채널의 `채널 삭제`는 이 Hub의 대화 캐시를 지우고 재동기화를 막습니다. Coral 서버 덤프와 작업 로그·산출물까지 지우는 기능은 아닙니다. 연결 설정이 달라지면 별도 보관 영역으로 취급합니다.


### 채널 작업 요약

채널 상단의 작업 요약에서 목표·결정 사항·남은 작업을 확인합니다. 기본값은 최근 협업/역할 작업의 요청, 최근 합의 결과, 진행 중·보류된 작업 기록입니다. 일반 대화를 AI로 추론한 요약은 아니므로 기록이 없는 항목은 직접 입력하세요. 요약 수정에서 저장한 내용은 자동으로 덮어쓰지 않습니다. 자동 요약으로 돌아가기로 직접 저장한 내용을 지울 수 있습니다. 보관·닫힌 채널에서도 편집할 수 있고, 새 채널로 이어갈 때 직접 저장한 요약을 복사합니다. 채널 삭제 시 요약도 삭제됩니다.


### 작업 알림

상단 알림함에서 최근 100개의 작업 완료·실패·확인 필요 알림을 확인하고 해당 채널로 이동합니다. 읽음 상태는 연결 설정별로 로컬에 저장되며 재시작 후 유지됩니다. 직접 취소한 작업은 알리지 않습니다. 채널을 삭제하면 해당 알림도 사라집니다. 데스크톱 알림은 버튼을 눌러 허용한 경우에만, 페이지가 열려 있고 다른 화면을 보는 동안 발생한 새 알림을 표시합니다. 페이지를 처음 열었을 때의 과거 알림은 팝업으로 보내지 않습니다. 브라우저를 닫으면 데스크톱 알림이 동작하지 않습니다.


### 독립 의견과 상호 토론

선택한 참여자 전원이 독립 의견을 제출할 때까지 다른 참여자의 답변·질문을 전달하지 않습니다. 제출 현황만 표시하며 실패·시간 초과 시 보류합니다. 모두 제출하면 작성자별 의견을 한꺼번에 공개하고, 전원이 상호 검토 후 반론에 답하고 의견을 수정합니다. 그 뒤 통합안을 작성해 모든 참여자가 같은 안을 검증합니다. 최종안 3회·호출 30회·45분 제한은 유지하며 합의 실패 시 미확정 초안과 남은 이견을 보여줍니다.


### 토론 기록을 Markdown으로 저장

채널 상단의 **토론 MD 저장**을 누르면 `.md` 파일을 내려받습니다. 채널 메시지, 저장한 작업 요약, 토론별 목차·요청·참여자·시간·단계, 질문과 반론, 최종 결과를 포함합니다. 코드 블록과 표는 Markdown으로 유지됩니다. 화면 검색·에이전트 필터와 관계없이 해당 채널에 저장된 전체 토론을 가져옵니다. 닫힌 채널과 보관 채널에서도 가능합니다. 진행 중에는 현재까지의 기록만 저장하며, 아직 공개되지 않은 독립 의견은 제외합니다. 별도 모델 호출은 없습니다.


### 사무실 말풍선과 팀 대화창

업무 사무실에서 새로 공개된 에이전트 발언을 캐릭터 위 말풍선으로 표시합니다. 여러 발언은 순서대로 8초씩 보여주며, 긴 내용은 일부만 표시합니다. 처음 진입할 때 과거 발언을 재생하지 않습니다. 아직 공개되지 않은 독립 의견은 표시하지 않습니다.

작은 불투명 **팀 대화** 창에는 현재 채널의 최근 공개 메시지 50개가 표시됩니다. 전체 채널을 보고 있다면 채널 이름도 함께 표시합니다. 창을 접거나 펼칠 수 있고, 위쪽 기록을 읽는 동안에는 스크롤 위치를 유지합니다. **새 메시지 · 아래로**로 최신 메시지로 이동합니다. 말풍선이나 메시지를 누르면 대화 탭에서 전체 내용을 확인할 수 있습니다. 좁은 화면에서는 대화창이 사무실 아래에 배치됩니다. 별도 모델 호출은 없습니다.


### 의견 표현과 조건 번호

새 토론 발언에는 **의견 → 근거 → 질문·남은 쟁점**의 공통 Markdown 작성 지침을 적용합니다. 최종 통합안은 요청에 맞는 독립된 결과물로 작성합니다. 기존 대화 원문은 변경하지 않습니다. 모델이 작성 지침을 따르는 방식이며 형식만을 위한 추가 모델 호출은 하지 않습니다.

조건 목록과 검토 근거에서는 내부 `R` 번호 대신 **사용자 조건 1**, **동료 질문 1**처럼 표시합니다. 항목 위에 마우스를 올리면 내부 추적 번호를 확인할 수 있습니다. 내부 검증과 명시적 조건 교체 기능의 식별자는 그대로 유지합니다.


### 넓은 사무실과 단계별 구역

사무실 탭으로 들어가면 상단 작업 요약을 접어 공간을 확보합니다. 작업 요약은 다시 펼칠 수 있습니다. **독립 의견 준비 → 토론·반론 → 최종 검토** 구역은 실제 진행 단계에 따라 강조되고, 에이전트는 담당 단계의 구역으로 이동합니다. 전체 채널 화면에서는 여러 구역이 동시에 활성화될 수 있습니다.

고정 상세 패널은 없어졌습니다. 캐릭터나 이름을 누르면 상세 창이 열리고 **닫기** 또는 **Esc**로 닫습니다. 데스크톱에서는 팀 대화창의 제목 부분을 드래그해 옮기고 오른쪽 아래 손잡이로 크기를 조절합니다. 두 곳 모두 키보드 방향키를 지원하며 **원위치**로 기본 배치로 돌아갑니다. 좁은 화면에서는 대화창을 사무실 아래에 고정하여 가림을 줄입니다.


### 오피스 캠퍼스 맵

업무 사무실은 유리 파티션, 라운드 가구, 식재와 테라스를 갖춘 사선 입체형 캠퍼스입니다. 개인 연구실·중앙 로비·토론 회의실·조율실·최종 검토실·라운지가 복도로 연결됩니다. 에이전트는 작업 단계에 맞춰 출입문과 복도를 거쳐 이동합니다. 통합안 작성은 별도 조율실에서 진행합니다.

맵을 드래그하거나 방향키로 이동하고, 휠 또는 **＋/−**로 확대·축소합니다. **전체 맵**은 전체 배치로 돌아가며 방 선택 메뉴로 원하는 공간을 볼 수 있습니다. **활동 따라가기**를 켜면 현재 단계의 방을 보여줍니다. 직접 드래그하거나 방을 선택하면 따라가기가 해제됩니다. 미니맵에는 에이전트 위치와 현재 보는 범위가 표시되며, 클릭으로 이동할 수 있습니다. 사무실 이동은 작업 상태의 시각화이며 에이전트 호출을 추가하지 않습니다.


### 탐색형 오피스 배치

현재 업무 사무실은 사선으로 압축한 모형 대신 **1680 × 1680 정방형 맵**을 사용합니다. 중앙 공용 공간을 중심으로 서쪽 연구실, 동쪽 회의실·조율실·검토실, 북쪽 리셉션, 남쪽 카페가 연결됩니다. 기본 화면은 일부 공간을 가까이 보여주며, 맵을 상하좌우로 탐색합니다. 전체 배치는 **전체 맵** 또는 미니맵에서 확인할 수 있습니다. 화면 크기가 바뀌어도 가로·세로 비율을 유지합니다.

공간 구성과 탐색 방식은 [ZEP 공식 오피스 소개](https://zep.us/home/office)를 참고했으며, 그래픽은 허브의 자체 SVG입니다. 사무실 탭에서는 작업 요약과 중복 설명을 숨겨 맵의 세로 공간을 확보합니다. 대화 탭으로 돌아가면 작업 요약을 다시 확인할 수 있습니다.


### 사무실 전체화면

사무실은 처음 열 때 전체 맵이 보입니다. **⛶ 전체화면**을 누르면 채널 목록과 헤더를 덮고 앱 화면 전체로 사무실을 펼칩니다. **전체화면 닫기** 또는 **Esc**로 돌아옵니다. 확대하거나 이동한 후 전체 배치를 다시 보려면 **전체 맵**을 누르세요.


### 공용 연구실과 에이전트 중심 보기

연구실은 구성원별로 생성하지 않고 하나의 공용 연구실을 사용합니다. 에이전트 구성이 달라져도 방 배치는 유지됩니다. 처음 진입하면 실행 중인 에이전트를 우선 선택해 확대하고, 이동하는 동안 카메라가 따라갑니다. 실행 중인 에이전트가 없으면 선택된 에이전트를 기준으로 합니다. 캐릭터나 하단 이름을 누르면 따라갈 대상을 바꿀 수 있습니다. 드래그·방 이동·전체 맵은 자동 따라가기를 해제하며, 따라가기 버튼으로 다시 켭니다. 전체화면에서도 따라가기는 유지됩니다.
